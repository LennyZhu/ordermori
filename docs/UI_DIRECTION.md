OrderMori 是**专为香港 IG Shop 和小型网店设计的轻量开单助手**，品牌理念为 **Create. Share. Track.**：快速开单、分享清楚专业的付款通知、跟进收款和发货。先体验开单，再配置店铺；Local-First、无需注册，尽量不依赖自建服务器，不扩展为复杂网店 SaaS。

本文定义视觉与体验方向，业务规则以 PRD 为准。订单有效性（订单状态）、付款状态、履约状态始终独立；任何设计不得以美观或减少步骤为由绕过金额锁定、取消 / 退款条件、真实创建计数或正式输出条件。本文及 PRD 均处于 Review Draft，不代表 Fully Approved 或 Frozen。

## 1. 视觉风格

已确认方向：**Premium Minimal — Warm White & Charcoal**。

暖白 + 深炭黑，专业极简，精致但信息紧凑。关键词：**Premium、Minimal、Professional、Calm、Elegant、Efficient、Trustworthy**。

- 暖白环境提供舒适感，深炭黑文字和主操作建立清晰层级；商家的商品、金额与收款信息优先。
- 以 iOS 熟悉的导航、表单、底部 Sheet、系统分享为基础，品牌体现在比例、字体、对齐、间距和克制细节。
- 风格面向小商家但不廉价，应专业、可靠、值得长期使用；不借装饰妨碍快速开单。
- 避免大面积彩色渐变、花哨装饰、厚重阴影、过多卡片嵌套、密集数据后台风格、过度动画及开发者工具感。
- 不为了极简而把提示藏起来、缩小文字或降低对比度；重要金额、状态和操作必须易读。

## 2. 初始色板

以下是设计讨论基准及 **Design Tokens 候选**，不是已测定或已冻结的最终值。应在真实界面、字号和状态组合中核对对比度与可读性。

| 用途 | 初始候选值 | 使用方向 |
| --- | --- | --- |
| Main Background | `#F7F6F2` | App 主背景，保持温暖、安静 |
| Primary Text / Button | `#20201F` | 主要文字与主按钮背景；按钮内容须保证对比度 |
| Surface | `#FFFFFF` | 表单、列表容器及独立付款通知画布 |
| Secondary Text | `#686762` | 次要说明，不能承载过淡的关键金额或唯一状态信息 |
| Border | `#E8E6E1` | 轻分隔线与边界，不用作唯一交互状态提示 |
| Muted Surface | `#EFEEE9` | 轻量分组或次级区域，不反复叠加底色 |

语义状态色少量使用：Paid 为低饱和墨绿，Awaiting Payment 为低饱和琥珀，Refunded / Error 为柔和砖红。语义色的具体色值待验证，不与商家的 Pro 品牌强调色混用。

状态必须同时有文字或可理解的图标语义，不能仅靠颜色识别。正文对比度目标至少 4.5:1，具体组合在设计与实现时检查，本文不声称已经通过。

## 3. 字体与布局

优先使用 iOS 系统字体与合适的繁体中文回退，保持数字、小数点、HKD 标识和双语混排清楚。下列尺寸为初始建议，可按实际内容调整，不是固定像素稿。

| 元素 | 初始建议 |
| --- | --- |
| 页面标题 | 28–30pt |
| 区块标题 | 20–22pt |
| 正文 | 15–17pt |
| 次要信息 | 12–14pt，须保证可读性，不用于唯一的金额或重要错误信息 |
| 重要金额 | 26–30pt，或按实际布局调整 |
| 页面左右间距 | 20pt |
| 区块间距 | 20–24pt |
| 主按钮高度 | 52–56pt |
| 输入区域 | 约 52pt 起 |
| 卡片 / 容器圆角 | 14–16pt，按信息分组使用，不逐行套卡片 |

- 支持 Dynamic Type 和系统字体缩放，布局随内容展开，不把放大文字裁成省略号。
- 交互触控区域通常不小于 44×44pt；数量步进、图标按钮和 Sheet 选项也需满足可操作性。
- English 与繁體中文（香港）分别检查标签、按钮、金额和长商品名的换行。
- 尊重安全区域与键盘；底部金额及操作区在键盘场景下仍清楚，不能遮挡正在编辑的字段。
- iPad 如纳入支持范围，使用合理限宽和居中内容，不将手机表单横向拉满；首发设备范围以 PRD 待确认项为准。
- 首版优先精心打磨浅色主题；深色主题暂列待评估，不在本轮宣称已设计。

## 4. 页面信息密度

正式方向是**精致但信息紧凑**。

- 首页减少无意义的独立卡片，优先白色列表容器 + 轻分隔线；不把每个数字、标签和操作再包一层卡片。
- 每屏尽量显示有效业务信息：买家、编号、金额、付款及履约状态。次要说明按需展开，不能挤占主任务。
- 金额、当前待办与主操作容易找到；以字体重量、对齐和间距建立层级，不依赖大量颜色块。
- 紧凑不等于缩小字体、压缩触控面积或隐藏错误；大字号下允许行高增加。
- 只显示待付款、已付款待履约等简单数量，不做营收图表、复杂 Dashboard 或后台式数据墙。

## 5. 首页 UI 与首次体验

### 5.1 首页结构

首页以待处理订单为中心，包含：顶部品牌 / 页面标题、待付款数量、已付款待履约数量、搜索、状态筛选、最近订单和“新增訂單”主按钮。

订单行突出买家标识（IG 用户名、称呼或客户代号）、应付金额、编号和日期；旧记录缺失标识时如实显示，不自动改写。付款与履约分开标记，取消、退款与商家流程已结束的订单可在历史查到，不伪装成待付款。

建议两个主要 Tab：**Orders / 訂單**、**My Shop / 我的店舖**。新增订单是独立主操作，不作为第三个主要导航 Tab；Tab 具体布局待设计验证。已有单草稿提供“继续”入口，不扩展为复杂草稿管理系统。

### 5.2 首次启动

- 一屏简洁欢迎页，主入口为“試用示例訂單”，次入口为“直接開始開單”；先体验开单，再配置店铺。
- 示例可改商品数量、单价及配送方式，即时看到金额和付款通知排版，始终明确标注示例。
- 示例不进入真实订单、不消耗 Free 额度、不写入真实最近商品、不包含可误用的真实二维码、不标记真实已付款，也不提供正式输出。
- 可跳过示例直接开真实订单，无强制注册、Pro 购买或完整店铺配置。真实订单可先填商品和保存，正式分享前才补必要资料。
- 首次必要配置只有店铺名称与至少一种可用收款方式及必要资料；Logo、感谢语、Pro 品牌配色均可稍后处理。

### 5.3 必须设计的状态

| 状态 | 体验要求 |
| --- | --- |
| 首次无订单 | 清楚的新建入口，可理解的空状态，不用虚构营业额或示例冒充真实记录 |
| 筛选无结果 | 解释当前筛选，可一键清除，不误报数据丢失 |
| 有订单列表 | 待办、金额和状态一眼可辨，搜索与筛选位置稳定 |
| 无待办订单 | 表达当前无待处理，历史仍可访问，不制造无意义提醒 |
| Free 额度接近用尽 | 显示累计已用 / 剩余，不出现月重置日期；提醒强度待设计验证 |
| Free 额度耗尽 | 创建第 11 张前先明示升级限制；第 10 张及其他已有订单仍可管理和按原状态约束分享，备份恢复不锁定 |

## 6. 快速开单 UI

正式采用**单页分区开单**，不做多步骤向导：

| 分区 | 主要内容 |
| --- | --- |
| 买家资料 | 首次创建真实订单时显示“買家標識（必填）”，可填 IG 用户名、称呼或客户代号，不要求真实姓名；电话、地址、邮箱、备注不强制 |
| 商品明细 | 最近 / 常用商品 Sheet、名称搜索、临时手填、多商品行、数量增减与单价编辑 |
| 配送与优惠 | 包郵、順豐運費到付、面交、自訂配送；固定金额折扣与商家运费 |
| 默认收款方式 | 采用店铺默认，可在权限允许时调整；已有订单使用自身快照，不能静默回填 |

商品选择采用轻量底部 Sheet：在同一上下文中找到最近 / 常用商品，按名称搜索，或立即手动输入临时商品。选择后带入默认价，仍可改数量与本单价格；不要求先维护目录，不加入 SKU、库存或复杂规格。

提供明确的“標記為常用”与“更新預設價格”轻量入口；临时输入不自动标为常用，示例不进入真实最近 / 常用。改本单单价与更新默认价是两个不同操作，不能自动联动；只有商家明确更新才改变默认价，且不影响历史订单。最近使用条目数量仍待验证，不为此新增复杂商品后台。

数量增减和价格变化即时计算。順豐運費到付明确提示“买家另向顺丰支付运费”，商家收取运费为 0，不表示商品货款到付；包郵、面交也为 0，自訂配送允许填写商家运费。切换方式清理旧运费时须提示。

底部固定层级：**应付总金额 → “預覽付款通知”主操作 → “儲存訂單”次操作**。两个按钮的名称和结果分开：预览不自动创建、不扣额度，首次成功保存真实订单才计数。

错误就近显示，定位到字段；键盘升起时滚动到可见输入，底部栏不能压住内容。从预览返回可继续改；切换 App 后恢复已持久化的轻量单草稿，不承诺恢复尚未持久化的瞬间输入，也不静默覆盖已有草稿。

买家必填校验仅在首次正式创建真实订单时触发，草稿可为空，示例用虚构资料，仅预览不拦截为缺买家标识。缺失时在字段旁提示“請填寫 IG 用戶名、買家稱呼或客戶代號。”并保留全部输入，不索取通讯录权限或额外个人资料，不强改历史订单。

历史订单详情的次要操作提供“複製為新訂單”：生成新标识的未保存草稿，带入可编辑的商品名、数量、单价；买家留空、折扣清零，配送需重新确认，默认收款来自当前可用店铺配置并须核对，不带旧二维码 / 账户快照、状态或时间。首次保存时生成新编号并校验买家与额度，保存前能核对总额；原单及既有草稿不被静默覆盖。

新建或复制第 11 张的限制必须在进入填写前清楚展示，并在保存时复核；复制进入草稿不计数，首次成功保存才计一次，不能绕过累计额度。不能把升级弹窗安排为填完整单后的首次告知。已有订单编辑仍受 PRD 金额锁定和状态权限约束。

## 7. 付款通知预览 UI

### 7.1 App 与通知画布

App 使用暖白背景，中央为独立纯白付款通知画布。App 的导航、提示和按钮位于画布外；实际导出包含的通知内容与正式预览一致，不把 App 操作栏或错误提示误导出。

主要操作为返回修改、切换模板、预览 / 放大检查和分享付款通知；次要操作为保存 PNG、复制付款文字。长商品明细可滚动并查看细节，金额与扫码区域可核对。

两款模板均为 Free 可用，不显示付费锁。付款文字与保存订单的金额、配送和单一收款方式一致，不默认复制电话、地址或内部备注。复制成功不表示已发送。

### 7.2 正式与非正式边界

- 示例画布醒目标明“示例 / 非真实订单”，无真实付款码，不能正式输出。
- 未保存草稿、缺店铺名或无可用收款资料时可看“非正式預覽”，显示具体缺项与修复入口；不能保存正式 PNG、复制付款文字或分享无效通知。
- 正式输出前先明确保存真实订单，再补齐并保存必要店铺 / 收款快照。预览按钮不在后台偷偷完成真实创建。
- 已建立、未付款、待履约且资料有效时才允许正式输出；已付款、退款或取消后保留历史查看，关闭催款式输出，不误称为已付款收据。
- 打开或关闭 iOS 系统分享面板均不意味着已发送，更不意味着已付款。失败、取消和系统完成回调使用准确文案，不显示“客户已收到”。
- 原订单使用过 Pro 外观而当前已取得有效撤销结果时，重新导出前提示：“目前已非 Pro，重新產生的付款通知將使用免費版樣式。”对仍可正式输出的未付款订单，预览与新导出均恢复 Made with OrderMori 及模板默认色；不改原业务、模板 / 强调色快照或已保存原 PNG。原文件未持久保存时如实说明，不伪装为仍有历史原图。
- 离线且未取得有效撤销结果时，保留合理的最后已确认权益；不能因网络未知就宣告 Pro 已撤销。已付款 / 退款 / 取消的输出限制不变，不增加收据或已付款确认图。

### 7.3 收款资料自适应

每张通知只采用一个明确收款方式，与 PRD 的 A–D 规则一致：

| 情况 | 画布表现 |
| --- | --- |
| A：官方二维码 + 有效文字 | 二维码为视觉重点，同时展示同一方式的 FPS ID 等必要资料 |
| B：只有官方二维码 | 清晰展示二维码，不虚构文字资料 |
| C：只有有效文字 | 清楚的文字收款区域，不显示空白二维码框 |
| D：无可用资料 | 缺项提示和补齐入口；非正式预览可看，正式输出不可用，无假二维码 |

二维码仅来自商家上传的官方来源图片，不生成未经验证的 FPS / PayMe 支付码，不裁切、不染色、不覆盖必要留白。可能含固定金额时，提示商家确认对象与当前金额适用性，不声称码中金额已经自动与订单一致。

配置提示与缺项校验按方式展示：FPS 文字可用一种适用的 FPS ID、关联 FPS 收款的手机号或邮箱，要求商家确认账户关联；PayMe 优先官方二维码，任意电话、普通网页链接或未经确认文本不视为有效资料，不自动生成、解析或验证 PayMe 码；银行转账文字须有银行名称、收款人名称和银行账号。二维码与文字必须属于同一方式和账户，不混入其他商家资料，不声称 App 已验证账户所属人或到账，也不上传开发者服务器。

必要资料不完整或不适用时，提示具体缺项，允许保存符合创建校验的订单及非正式预览，禁止正式输出无效通知；B 的有效官方二维码单独展示仍可用，不虚构文字。

## 8. PNG 模板设计

必须区分 App UI 与实际生成的付款通知。正式通知标题统一为 **付款通知 / Payment Notice**，清楚说明不是正式收据或已收款确认；保持业务内容与金额准确。

### 8.1 Editorial Minimal / 黑白极简

白色背景、黑色主文字、克制细线和精致字体层级。店铺品牌优先，金额突出，明细对齐，收款区域清楚；精致来自比例和排版，不通过细小浅字伪造品质感。

### 8.2 Soft Korean / 韩系柔和

以柔和低饱和配色、干净结构和适度品牌细节建立亲切感。通知基础画布保持纯白，可在允许区域使用柔和色；不以色块、纹理或装饰影响文字、金额和二维码。

### 8.3 共同要求

- 两款模板均支持 Free / Pro、商家 Logo、长商品名称、动态高度、官方二维码、文字收款资料、自适应 A–D 展示及 English / 繁體中文。
- 1080px 宽为初步验证目标，高度依内容变化；最长明细按 PRD 输入边界验证。商品名正常换行，不截金额、不挤坏二维码，也不把内容缩至难读。
- Free 底部保留小型 **Made with OrderMori**，不抢店铺品牌、不遮内容或二维码；有效 Pro 可移除该标记，付款通知说明仍保留。
- Pro 仅允许少量经过设计的品牌强调预设色，作用于指定品牌视觉区域，不提供任意模板编辑器，不修改官方码的图像、颜色或留白，不降低文字对比。
- 文字资料只有真实已提供内容；不为排版完整而捏造账户、放空白码框或假码。
- 实际经 WhatsApp 手动分享、由另一设备接收后核对清晰度与扫码结果，不能只看本机预览即判定通过。
- 预览、生成、PNG 保存、复制或分享均不自动标记已付款；不能把模板设计成假收据。

## 9. 店铺设置 UI

使用简洁分组列表，避免复杂管理后台：

| 分组 | 内容与交互 |
| --- | --- |
| 店舖資料 | 店铺名称，Logo 可选；先说明必要项，不强迫完善全部品牌资料 |
| 收款方式 | 按 FPS / PayMe / 银行转账展示第 7.3 节必要资料及缺项提示，保留单一默认方式；商家确认来源、账户关联与适用性，不暗示自动核验账户或到账 |
| 付款通知設定 | 两款 Free 模板、可选感谢语、Pro 预设品牌强调色；不提供任意布局编辑器 |
| 資料與備份 | 主动导出 / 整体恢复；说明含个人及收款资料、替换前确认、失败不破坏当前数据；不假装云同步 |
| OrderMori Pro | 当前权益、累计前 10 张真实订单用量、升级和恢复购买；模板与备份不设 Pro 门槛 |
| 語言與關於 | English / 繁體中文（香港）及必要关于信息，不暴露调试或实现术语 |

首次配置只要求店铺名称与至少一种可用收款方式及必要资料，其他均可跳过。真实订单可先保存；缺项仅限制正式输出，不阻止先体验开单。

店铺变更不回写历史快照；尚可编辑的未付款订单须明确应用新资料。图片损坏或恢复失败时保留旧记录，不自动拿当前设置覆盖旧图。

## 10. Pro 购买页 UI

与 App 同样采用暖白 + 深炭黑，清楚展示：**无限创建订单、移除 Made with OrderMori 品牌标记、少量预设品牌强调色**，并说明 **Apple Non-Consumable IAP 一次性买断**。

购买页须清楚展示：“一次性購買 · 無訂閱月費 · 不設使用期限”。正常购买权益不因时间经过而到期；Apple 已确认退款、撤销等特殊交易情况继续按 PRD 处理，不引入订阅续费或周期授权验证机制。

Free 为**每个本地数据档案累计前 10 张真实订单免费，不按月重置**；两款模板、Logo、PNG 导出分享、基本订单管理和完整备份恢复均可用。第 10 张继续可管理和按原状态约束分享；第 11 张新建 / 复制前先展示限制，已有数据不成为购买筹码。

- 价格必须来自 Apple 商店商品返回的对应地区实际本地化售价。**HK$88 仅为香港候选价格，待验证**，不是已确定售价，不可作为商店价格缺失时的替代。
- 购买与“恢复购买”入口均清楚；价格未取得、无网络、取消、待处理、失败及无可恢复记录分别反馈，不虚假成功、不连续自动重试扣款。
- 权益以有效 Apple 购买记录为依据，保留合理的离线已确认权益；备份文件不能直接授予 Pro。恢复订单数据与恢复购买明确分开。
- 首版无订阅、广告、订单额度充值包或复杂会员等级；不使用虚假倒计时、误导性价格、频繁强制弹窗或付费锁模板。
- 取得有效退款 / 撤销结果后，不删除订单、不改历史业务或模板 / 强调色快照，不覆盖已生成 / 保存 / 发送的原 PNG。符合状态条件的新导出采用 Free 标记及模板默认色，先按第 7.2 节提示；不能继续已撤销的 Pro 导出权益。原图未持久保存时不声称文件仍在；离线未知状态沿用合理已确认权益。

## 11. 动效与辅助功能

动效简短、自然、克制，用于按钮反馈、页面过渡、状态变化、PNG 生成进度及保存结果。不做夸张开场或装饰性循环动画，支持减少动态效果。

- **VoiceOver**：输入、数量步进、金额、状态和图标按钮有可理解标签；按业务顺序朗读，错误可被发现，状态不只靠颜色。
- **Dynamic Type**：字号增大后内容和控件可展开，不能裁掉金额或主操作，也不能用整体缩放抵消系统字号选择。
- **对比度**：核对正文、次要文字、状态标签、错误、禁用及按钮；Pro 强调色不改变语义色或降低可读性。
- **安全区域与键盘**：避开底部系统区域；键盘、Sheet 或提示出现后焦点与正在编辑字段仍可见，不压住金额或按钮。
- **iPhone / iPad**：在确认的支持设备检查；iPad 合理限宽、不铺满手机表单，首发支持范围仍待确认。
- **双语**：English 和港式繁体中文的长标签、商品名、金额与错误提示均需实测，不机械压缩一套语言来适配另一套。
- **反馈准确**：生成中防止重复操作；保存成功、失败、分享取消各有对应结果，不能把“面板已打开”反馈为已送达或已付款，不显示虚假进度。

## 12. UI 设计验收要求

下表为后续设计与实现的可检查标准，**本次尚未执行真机 UI、购买或扫码验收**。应结合 PRD 第 14 节检查；未决事项先人工确认，不用视觉稿替代业务决策。

| 编号 | 检查项 | 通过条件 |
| --- | --- | --- |
| UI-01 | 首页待办 | 第一屏能找到待付款及已付款待履约数量、新增入口；订单行的买家、金额、编号和独立状态可辨 |
| UI-02 | 信息密度 | 无无意义卡片嵌套或营收图表，紧凑仍有足够字号与点击面积，不呈现后台感 |
